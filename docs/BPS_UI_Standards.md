# Blender Production System (BPS)

# UI Standards

Version: 1.0

Author: Patrice Newson

---

# Purpose

This document defines the user interface standards for Blender Production System (BPS).

Every Studio should provide a consistent, predictable, and professional experience.

A user should immediately recognize any Studio as part of the Blender Production System.

---

# Design Philosophy

The interface should be:

• Clean

• Consistent

• Professional

• Production-focused

• Easy to navigate

The goal is to reduce distractions while guiding users through the production pipeline.

---

# Studio Layout

Every Studio should follow the same structure whenever applicable.

Studio Title

↓

Purpose

↓

Foundation

↓

Tools

↓

Validation

↓

Production

↓

Status

This consistent layout allows users to quickly understand each Studio.

---

# Studio Header

Each Studio should include:

Studio Name

Studio Icon

Clear Purpose

Example

Character Studio

Purpose:

Create and manage production-ready characters.

---

# Section Layout

Each section should use a boxed layout.

Example

FOUNDATION

TOOLS

VALIDATION

PRODUCTION

Sections should always appear in the same order.

---

# Buttons

Buttons should:

Use descriptive names.

Be vertically aligned.

Use consistent heights.

Group related actions together.

Preferred button height:

1.3

Large production actions:

1.4

---

Icons should match the task.

---

# Typography

Use clear section titles.

Avoid abbreviations unless commonly understood.

Example

Generate Base Mesh

Instead of

Gen Mesh

---

# Naming

Studios should always use:

Character Studio

Blueprint Studio

Modeling Studio

Rigging Studio

Materials Studio

UV Studio

Texture Studio

Animation Studio

Rendering Studio

Certification Studio

Reports Studio

Settings

Avoid inconsistent naming.

---

# Color

Use Blender's native theme.

Do not rely on custom colors.

Status should be communicated through:

Icons

Progress

Labels

Certification

Not custom color themes.

---

# Expandable Panels

Studios should be collapsible.

Users should only open the departments they are currently using.

---

# Validation

Validation should always appear near the bottom of a Studio.

Validation should answer:

Is this production-ready?

---

# Production Status

Every Studio should eventually display:

Current Status

PASS

FAIL

IN PROGRESS

NOT STARTED

---

# Future Dashboard

Version 2.0 introduces the Production Dashboard.

Dashboard displays:

Current Character

Current Studio

Production Progress

Certification Progress

Production Health

Recent Reports

The Dashboard becomes the landing page of BPS.

---

# Accessibility

Buttons should remain readable on:

Small monitors

Large monitors

Laptop displays

High DPI displays

Avoid overcrowding.

---

# User Experience Goals

Every Studio should:

Require minimal clicks.

Present information clearly.

Provide meaningful feedback.

Guide users naturally through the pipeline.

Reduce unnecessary decisions.

---

# Consistency Rules

Every Studio should feel like another department inside the same software.

A user who understands one Studio should immediately understand every other Studio.

---

# Goal

Create a professional production environment that feels cohesive, scalable, and intuitive while supporting every stage of character production.
